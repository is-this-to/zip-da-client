# 주요 기능

## 1. 지도 기반 매물 검색

현재 지도 영역과 확대 단계를 기준으로 공개 매물을 조회한다. 지도 결과와 목록 결과는 동일한 필터를 사용하며 지도 이동, 필터 적용과 정렬 변경 시 함께 갱신된다.

### 1.1. 지역 검색과 지도 이동

- 지역명 검색
- 행정구역 중심 좌표·경계·지도 영역 조회
- 지역 선택 시 해당 영역으로 지도 이동
- 지도 확대 단계별 집계·마커 표시

### 1.2. 검색 필터

- 매물 유형과 거래 유형
- 매매가, 보증금, 월세와 관리비
- 전용면적과 방 개수
- 집주인·세입자 직접 등록과 중개사 매물
- 사용승인일, 주차, 엘리베이터와 반려동물
- 최신순, 가격순과 면적순 정렬

### 1.3. 요청 제어

- 지도 이동이 끝난 뒤 debounce를 적용하여 불필요한 연속 조회 방지
- 새 검색이 시작되면 `AbortController`로 이전 요청 취소
- 요청 순서와 검색 조건을 비교하여 최신 결과만 화면에 반영
- 지도와 목록에서 동일한 검색 조건·정렬·페이지 상태 공유
- 목록 하단 진입 시 커서 기반으로 다음 결과 조회

```text
[지도 화면 진입]
    │
    ▼
Kakao Maps SDK로 지도 생성
    │
    ├─ idle 이벤트 등록
    │    └─ 지도 이동·확대가 끝난 시점에 현재 영역 검색
    ├─ zoom_changed 이벤트 등록
    │    └─ 확대 단계에 맞는 지역 경계 다시 조회
    ├─ 마커 click 이벤트 등록
    │    └─ 선택한 매물 정보와 상세 화면 연결
    └─ ResizeObserver 등록
         └─ 화면 크기 변경 시 지도 영역 재배치
    │
    ▼
[지도 이동 또는 검색 조건 변경]
    │
    ▼
Debounce로 연속 동작 정리
    │
    ▼
Pinia 검색 요청
    │
    ├─ 이전 요청 진행 중 → AbortController로 취소
    └─ 현재 검색 조건과 요청 순서 기록
    │
    ▼
Property API 호출
    │
    ├─ 최신 조건과 일치 → 마커와 목록 갱신
    ├─ 이전 검색의 늦은 응답 → 화면 반영 제외
    └─ 조회 실패 → 실패 상태 표시
    │
    ▼
[지도 화면 종료]
    │
    └─ 지도 이벤트·관찰 객체·타이머·진행 중인 요청 정리
```

> **최신 검색 결과 유지**
>
> **구현 방식** · 지도·검색 이벤트마다 debounce 타이머를 초기화하고, `AbortController`로 진행 중인 요청을 취소한다. 요청 순서 식별자와 정규화한 검색 조건 식별자를 함께 비교하여 현재 검색과 일치하는 응답만 상태에 저장한다.  
> **화면 효과** · 지도 이동과 필터 변경이 연속되어도 오래된 응답이 최신 검색 결과를 덮어쓰지 않도록 처리한다.

## 2. 매물 조회와 관리

### 2.1. 매물 상세

- 공개 매물 정보와 이미지 조회
- 매물 위치와 거래·건물·옵션 정보 표시
- 조회 중 로딩 표시와 조회 실패·존재하지 않는 매물 안내

### 2.2. 단계별 매물 등록

`등록 주체 → 기본 정보 → 주소·단지 확인 → 옵션·이미지 → 최종 확인`의 5단계 화면으로 구성한다.

- 단계별 입력값 검증과 오류 항목 안내
- 카카오 주소 검색 결과를 이용한 주소·단지 확인과 지도 위치 표시
- 이전 단계로 이동해도 입력 내용 유지
- 등록 처리 중 버튼을 잠가 중복 제출 방지
- 동일한 등록 요청에는 같은 `Idempotency-Key`를 재사용하여 중복 매물 생성 방지

> **중복 매물 생성 방지**
>
> **구현 방식** · 단계별 입력 상태를 최종 요청 데이터로 조합하고, Web Crypto API의 SHA-256으로 요청 지문을 생성한다. 완료되지 않은 동일 요청은 `sessionStorage`에 저장한 UUID 기반 멱등성 키를 재사용하고 등록 성공 시 제거한다.  
> **화면 효과** · 단계 이동 시 입력값을 유지하고, 중복 클릭이나 실패 후 재요청으로 같은 매물이 여러 번 생성되는 문제를 방지한다.

### 2.3. 이미지와 검증 서류 업로드

`업로드 세션 생성 → 업로드 URL로 파일 전송 → 체크섬·크기 확인 후 완료 처리` 순서로 파일을 등록한다.

- 파일 선택과 업로드 진행 상태 표시
- 업로드 중 단계 이동 제한
- 실패한 파일의 오류 안내
- 소유자·임차인 검증 신청 서류 연결

> **파일 업로드**
>
> **구현 방식** · 파일명·크기로 업로드 세션을 생성하고, 서버에서 발급한 업로드 URL과 필수 요청 헤더를 이용해 Fetch API의 `PUT` 요청으로 파일을 전송한다. 이후 브라우저에서 계산한 체크섬과 파일 크기를 완료 API에 전달한다.  
> **화면 효과** · 업로드가 확인된 파일만 매물 이미지와 검증 신청 서류에 연결하고, 처리 중 단계 이동이나 불완전한 제출을 방지한다.

### 2.4. 내 매물 관리

- 내 매물 목록 조회와 스크롤에 따른 다음 목록 불러오기 (커서 기반 추가 조회)
- 매물 정보 수정, 거래 상태 변경과 삭제
- 수정·상태 변경·삭제 요청에 현재 버전과 `If-Match` 전달
- 다른 요청이 먼저 매물을 변경한 경우 충돌 상태를 화면에 안내
- 처리 중인 작업을 구분하여 중복 요청 방지

```text
[내 매물 조회]
    │
    └─ 매물 데이터와 현재 버전 수신
       예: version = 7
    │
    ▼
[수정·상태 변경·삭제·검증 요청]
    │
    ├─ 요청 본문에 version = 7 포함
    └─ HTTP 헤더에 If-Match: "7" 전달
    │
    ▼
Property 서비스의 버전 비교
    │
    ├─ 서버 버전 = 7 → 요청 처리
    │                   → 응답의 최신 데이터·버전으로 화면 갱신
    └─ 서버 버전 ≠ 7 → 다른 변경이 먼저 반영된 상태
                        → 요청 거부 후 최신 정보 재조회 안내
```

> **최신 상태 작업**
>
> **구현 방식** · 조회 당시의 버전 값을 요청 본문과 HTTP 조건부 요청 헤더인 `If-Match`에 함께 전달한다. 서버는 저장된 현재 버전과 비교하여 일치하는 요청만 처리하며, 버전 충돌 응답은 일반 오류와 분리하여 관리하고 수정 화면과 관리 목록에서 최신 데이터 재조회를 제공한다.  
> **화면 효과** · 오래된 화면의 요청이 최신 매물 정보를 덮어쓰지 않도록 하고, 충돌 발생 시 최신 상태에서 다시 작업할 수 있도록 한다.

## 3. 회원 기능

### 3.1. 이메일 인증 회원가입

- 서버가 반환한 만료 시간을 이용한 인증 타이머
- 인증번호 재발송과 입력 횟수 제한
- 인증 완료 후 기본 정보 입력과 회원가입

```text
[Vue 3·Pinia | 이메일 인증 요청]
    │
    ▼
Member 서비스
    │
    ├─ 가입된 이메일·재발송 제한 확인
    ├─ 6자리 인증번호 생성
    └─ 이메일·인증번호를 해시하여 5분 만료로 저장
    │
    ▼
[인증번호 이메일 발송]
    │
    └─ 프론트는 서버가 반환한 만료 시간으로 타이머 실행
    │
    ▼
[사용자 인증번호 입력]
    │
    └─ 인증 식별자·이메일·6자리 인증번호 전달
    │
    ▼
Member 서비스 인증
    │
    ├─ 인증 목적·이메일·만료·사용 여부 확인
    ├─ 인증번호 해시 비교
    ├─ DB 행 잠금으로 동시 확인 요청 제어
    └─ 5회 실패 시 추가 확인 제한
    │
    ├─ 성공 → 인증 완료 후 회원가입 진행
    └─ 실패 → 오류 안내 또는 새 인증번호 요청
    │
    ▼
[회원가입 요청]
    │
    └─ 서버에서 인증 완료 여부 재확인
       → 가입 성공 후 사용한 인증 정보 제거
```

> **이메일 소유 확인**
>
> **구현 방식** · 인증번호와 이메일은 해시하여 저장하고, 만료 시간·재발송 간격·입력 횟수를 제한한다. 인증 확인 시 DB 행 잠금으로 동시 요청을 제어하며, 회원가입 단계에서 인증 목적과 완료 여부를 서버가 다시 검증한다.  
> **화면 효과** · 남은 시간과 재발송 상태를 안내하고, 인증을 완료한 이메일만 회원가입에 사용할 수 있도록 한다.

### 3.2. 계정 관리

- 로그인과 토큰 재발급
- 비밀번호 재설정·변경
- 회원 프로필 수정
- 입력 오류를 해당 항목에 표시하고 처리 상태에 따라 버튼 제어

## 4. 중개사 전환

### 4.1. 신청 서류 업로드와 비공개 열람

- 사업자등록증과 중개사무소등록증 파일 형식·크기 확인
- 신청 서류 비공개 저장
- 신청자 소유권 또는 심사 관리자 권한 확인
- 권한 확인 후 5분 만료 Signed URL 발급
- 관리자 서류 열람 감사 이력 기록

```text
[사업자등록증·중개사무소등록증 선택]
    │
    ├─ 허용 형식: PDF·JPG·PNG
    └─ 최대 크기: 10MB
    │
    ▼
Member 서비스 파일 검증
    │
    ├─ MIME 유형 확인
    ├─ 파일 확장자와 MIME 유형 일치 확인
    └─ 파일 시작 바이트로 실제 파일 형식 확인
    │
    ├─ 검증 실패 → 저장하지 않고 업로드 거부
    │
    ▼
MinIO 비공개 서류 저장
    │
    ├─ 서류 저장 키 생성 후 원본 파일 저장
    └─ 소유 회원·서류 종류·저장 키·MIME 유형
       ·파일 크기·체크섬·PRIVATE 상태를 DB에 기록
    │
    ├─ DB 기록 성공 → 업로드 완료
    └─ DB 기록 실패 → 저장된 MinIO 객체 삭제
                       → 파일과 DB의 불일치 방지
    │
    ▼
[서류 열람 요청]
    │
    ├─ 신청자 본인 → 5분 만료 Signed URL 발급
    ├─ 심사 관리자 → 5분 만료 Signed URL 발급
    │                  → 서류 열람 감사 이력 기록
    └─ 권한 없음 → 접근 거부
```

> **비공개 신청 서류 보호**
>
> **구현 방식** · 프론트엔드에서 확장자·MIME 유형과 10MB 제한을 확인하고, Member 서비스에서 확장자·MIME 유형·파일 시그니처를 다시 검증한다. MinIO에 원본을 저장하고 소유자·서류 종류·저장 키·크기·체크섬과 `PRIVATE` 상태를 DB에 기록하며, DB 기록 실패 시 저장 객체를 삭제한다. 서류는 신청자 소유권 또는 심사 관리자 권한을 확인한 뒤 5분 만료 Signed URL로 제공한다.  
> **화면 효과** · 신청 서류를 공개 경로에 노출하지 않고 권한이 확인된 사용자에게만 제한된 시간 동안 제공한다.

### 4.2. OCR 기반 신청 정보 자동 입력

- 서류별 OCR 처리 상태와 실패 사유 표시
- 사업자등록번호·개업일자·대표자명 자동 입력
- 중개사무소 등록번호·중개사무소명 자동 입력
- OCR 원문 확인과 인식값 수정
- 필수값 검증 후 신청 제출
- 인식 실패 시 서류 재업로드

```text
[Vue 3·Axios | 신청 서류 업로드]
        │
        ▼
[Member·Spring Boot | 파일 형식별 OCR 처리]
        │
        ├─ JPG·PNG → Google Cloud Vision API 문서 텍스트 인식
        │
        └─ PDF → Google Cloud Storage 임시 저장
                   ↓
                Google Cloud Vision API 비동기 PDF 인식
                   ↓
                페이지 순서대로 결과 결합
                   ↓
                임시 입·출력 객체 정리
        │
        ▼
[Java 정규 표현식 | OCR 원문 정규화·항목 추출]
        │
        ▼
[Pinia | OCR 상태·추출 정보 관리]
        │
        ├─ 성공 → Vue 3 Composition API 입력 폼에 자동 반영
        │          → 사용자 확인·수정·제출
        └─ 실패 → 실패 사유 표시
                   → 서류 재업로드
```

> **OCR 입력 자동화**
>
> **구현 방식** · JPG·PNG 이미지는 한국어·영어 언어 힌트를 적용한 문서 텍스트 감지 API로 직접 처리하고, PDF는 Cloud Storage의 임시 객체를 이용해 비동기 OCR로 처리한다. PDF 결과는 페이지 순서대로 결합한 뒤 임시 입·출력 객체를 정리한다. 추출 원문은 문서 유형별 정규 표현식으로 구조화하고, 프론트엔드는 반환된 정보를 반응형 신청 폼에 매핑하여 사용자 보정과 입력값 검증 후 제출한다.  
> **화면 효과** · 서류의 주요 정보를 신청 화면에 자동 입력하여 반복 입력을 줄이고, 사용자가 OCR 원문과 비교해 잘못 인식된 값을 수정할 수 있도록 한다.
